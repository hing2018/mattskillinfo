    Matt Skills

    一分鐘快速上手

    第一次用這套技能，先跑這三步就夠了。

    1. 第一步

      /setup-matt-pocock-skills

      決定 issue 追蹤在哪、標籤怎麼分類、文件放哪。其他工程類技能都依賴它，沒跑過會缺規格。只跑一次。

    2. 第二步

      /ask-matt

      不知道用哪個技能時，問它。它是全技能集的路由器，會告訴你該走哪條流程——只導覽，不執行。

    3. 第三步

      /grill-me

      有想法先被拷問。連續追問把你的計畫漏洞挖出來，確認有共識之後才會動手。

    我現在該用哪個？

    點每一項展開對應的技能。

    • 完全不知道該用哪個
      • ask-matt
    • 有一個想法／計畫，想先被壓力測試
      • 想被一題一題問 → grilling
      • 想一次問完所有關鍵問題 → batch-grill-me
      • 邊問邊要把決策與術語落檔 → grill-with-docs
      • 要把某個流程問成可重複規格 → loop-me
      • 卡在只有別人知道答案的決定 → to-questionnaire
    • 討論完了，要變成可執行文件
      • 寫成正式規格 / PRD → to-spec
      • 拆成一張張小任務 → to-tickets
      • 工程大到一個 session 做不完 → wayfinder
    • 要寫程式
      • 手上已有 spec 或 ticket → implement
      • 測試先行（紅→綠→重構）→ tdd
      • 還不確定設計對不對 → prototype
      • 想改架構但不知從哪下刀 → improve-codebase-architecture
    • 出事了
      • 壞掉／報錯／變慢，找不到根因 → diagnosing-bugs
      • merge / rebase 卡住 → resolving-merge-conflicts
      • 要規劃一次重構 → request-refactor-plan
    • 產出東西了，要交出去
      • 審查分支 / PR / WIP → code-review
      • 使用者回報 bug，要開單 → qa
      • issue / PR 亂成一團要整理 → triage
    • 團隊／架構層面
      • 統一術語、寫決策紀錄 → domain-modeling
      • 只想要一份詞彙表 → ubiquitous-language
      • 設計模組介面、找深淺 → codebase-design
      • 要多套完全不同的介面來比 → design-an-interface
      • 強制 TS 套件的模組邊界 → setup-ts-deep-modules
    • 寫作／教學／查資料
      • 查一個主題，要一手來源 → research
      • 改一篇既有文章 → edit-article
      • 教我一個新觀念（多堂課）→ teach
      • 寫文章：還在發想 → writing-fragments
      • 寫文章：素材有了要節拍 → writing-beats
      • 寫文章：素材有了要段落 → writing-shape
      • 幫我寫出一個好技能 → writing-great-skills
      • 建置課程練習目錄骨架 → scaffold-exercises
    • 環境／工具維護
      • 第一次用這套技能 → setup-matt-pocock-skills
      • 提交前自動跑檢查 → setup-pre-commit
      • 擋掉危險 git 指令 → git-guardrails-claude-code
      • 把手動流程包成互動腳本 → wizard
      • 管理 Obsidian 筆記 → obsidian-vault
      • 設定 AI 代理的行為準則 → behavior
      • 把測試的 as 斷言換掉 → migrate-to-shoehorn
      • 換 session／換代理接手 → handoff · claude-handoff

    附錄 C · 已知缺陷與注意事項

    1. grilling 與 batch-grill-me 設計衝突：一個要求一次一題、一個要求一次問完。兩者是並存兩套做法，不是同一技能的兩種模式。
    2. 格式損壞的翻譯檔：implement/CHINESE.md 前置結構錯亂（缺 frontmatter）； code-review/CHINESE.md 第 1 行的中文描述被誤置在 --- 之前，導致 frontmatter 解析失效。
    3. 內容漂移：codebase-design/CHINESE.md 第 18 行殘留未翻譯的英文 “otherwise”； wizard/CHINESE.md 把原文的 “both” 譯成「兩者都不是」，語意相反。
    4. 文件與程式不一致：setup-ts-deep-modules 文件寫「四條規則」， 但 dependency-cruiser.config.cjs 實際有五條。
    5. 版本落差：prototype 本機版是「終端 TUI 小程式」的舊版，上游已改為「單一可分享的 HTML 檔」。
    6. 循環相依：tdd 把重構推給 code-review， 而 implement 又要求收尾呼叫 code-review。實務上要自己決定順序。
    7. 路徑寫死：obsidian-vault（WSL 路徑 /mnt/d/…）、 scaffold-exercises（ai-hero-cli）無法直接搬到其他專案。
    8. 上游清單可能過期：ask-matt 內嵌的技能清單與本機實際安裝的不同步， edit-article 與三個 writing 技能它都沒提到。
    9. 精簡版技能：implement、triage、 research、edit-article 檔案極短（12～15 行），相較其他技能屬明顯精簡版。
    10. 前端編號前綴：各 SKILL.md frontmatter 的 name 帶 [01]～[42] 編號是本地加的排序前綴， 實際 slash 指令名是不帶前綴的資料夾名。
